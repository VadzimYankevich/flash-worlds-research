# Программа, обогнавшая сегментное решето в проверенном маршруте

В архив включены **те самые исходники, на которых получены измерения**. Измеренный вариант — `CandidatePrime` из `src/candidate_work/flash_candidates.py`, режим `candidate_prime`, с выключенной диагностикой. Он выполняет точное деление на простые из сохраняемого малого базиса. В исходном опыте медиана парного отношения `время решета / время нашего варианта` составила **2,788**, в повторе — **2,760**.

Результат относится к коротким окнам и к включённому сегментному решету на Python. Оптимизированный C/C++ `primesieve` в данном маршруте не измерялся. Учебная программа `flash_worlds_demo.py` и новый сертификат ряби `ripple_smooth_certificate.py` решают свои задачи; их времена не подставлены в это сравнение.

## 1. Где находятся исходники

| Файл | Что реализует |
|---|---|
| `src/candidate_work/flash_candidates.py` | `CandidatePrime`, непосредственное хранение адресов, контроллер `FlashRunner`, командная строка |
| `src/candidate_work/candidate_sieves.py` | Общий тип малого базиса `SmallPrimeBasis`, сравниваемый `CandidateSegmentedSieve`, проверка допустимости окна |
| `src/candidate_work/candidate_validation.py` | Независимая проверка окон, максимумов, суффиксов и факторных свидетельств после завершения расчёта |
| `src/strong_baseline_probe.py` | Неизменённый протокол 36 замеров трёх движков; отдельная реализация MR12 |
| `src/reproduce.py` | Сверка исходников со снимками, проверка исходных JSON/CSV, безопасный повтор замеров |

`data/benchmark_original.json` содержит полные снимки измеренных исходников и их SHA-256. `reproduce.py` проверяет побайтовое совпадение. Архив не подменяет измеренный движок переписанным учебным примером.

Исторический адаптер `legacy_periods` оставлен в замороженном исходнике, но его старый вспомогательный каталог в пакет не входит. Для воспроизведения заявленного результата используется именно `candidate_prime`.

## 2. Как работает поиск

### Контроллер вспышек

`FlashRunner` начинает с опоры `B=3`. Для каждой опоры вычисляется безопасный правый предел `G(B)=min(B²,3B+4)`. Рассматриваются нечётные адреса короткого окна, не более 15 позиций. Нижняя граница учитывает уже закрытый суффикс предыдущего мира:

```text
upper = G(B)
lower = max(B+2, previous_R+2)   # previous_R отсутствует в первом мире
```

Контроллер передаёт движку готовые `B,L,R`. Если окно полностью составное, он сдвигает следующее окно влево. Если найден простой максимум, он сохраняет точное описание закрытого суффикса справа и переходит к новой опоре. Оба конкурирующих движка получают один и тот же тип задачи под этим общим контроллером.

### Проверка одного окна

`CandidatePrime` идёт от R вниз с шагом 2 и останавливается на первом доказанном простом.

1. Если факт об адресе уже сохранён, берётся его готовое значение.
2. Сначала проверяются делители 3 и 5, когда они не превосходят квадратный корень. Найденный делитель сразу закрывает адрес.
3. Только для прошедшего эти проверки кандидата малый базис достраивается до `isqrt(n)`.
4. Из сохранённого списка проверяются простые больше 5 и не больше `isqrt(n)`. Первый делитель завершает проверку составного.
5. Если весь необходимый набор пройден без делителя, адрес прост. На этом поиск в окне заканчивается: позиции левее его максимума для поставленной задачи не нужны.

Нечётные составные имеют простой делитель не больше квадратного корня, поэтому завершённая проверка точна. В рабочем ядре нет вызовов Миллера — Рабина. Этот факт не делает перебор до корня быстрым для произвольно больших чисел.

### Что сохраняется

| Объект | Содержимое и назначение |
|---|---|
| `CandidateBase.facts` | Адрес → найденный делитель либо признак уже доказанной простоты |
| `SmallPrimeBasis.flags` | Уже построенный нечётный префикс решета малого базиса |
| `SmallPrimeBasis.primes` | Явные адреса простых малого базиса |
| `FlashRunner.answers` | Готовые ответы для конкретных троек `(B,L,R)` |
| `windows`, `steps`, `anchors` | Адреса максимумов, описания окон и сертификаты закрытых суффиксов |

Базис расширяется отдельно от поиска далёкого окна. Старые флаги и список простых сохраняются; `prepare(limit)` возвращает принадлежащий базису список и индекс конца нужного префикса. Обход через `islice` не копирует весь список. Новые простые извлекаются из готовых флагов через `bytearray.find`, пропускающий нулевые промежутки внутри реализации Python.

Адреса не восстанавливаются из комплексных моментов. В этом ядре не вычисляются моменты, объединения арифметических прогрессий или CRT-пересечения. Поле `queries` в диагностике считает обычные вызовы поиска окна; это не обслуживание универсального запроса к базе.

В возрастающем маршруте данного сравнения окна не пересекаются. Поэтому попаданий в кэш уже решённых адресов и одинаковых окон нет. Явное хранение предотвращает потерю сведений, но приписывать ему выигрыш времени через повторные попадания в кэш здесь нельзя. Малый базис действительно используется повторно между вспышками.

## 3. Что делает сравниваемое решето

`CandidateSegmentedSieve` имеет собственный экземпляр **того же типа** `SmallPrimeBasis`. Для удалённого окна оно достраивает базис до `isqrt(R)`, создаёт флаги нечётных позиций окна и для каждого базового простого вычисляет первое допустимое кратное. Если кратное попало в окно, выполняется вычёркивание; если не попало, проверка периода всё равно уже оплачена. Максимум затем находится через `rfind` по готовым флагам.

Для начальных близких окон предусмотрен доступ к уже сертифицированному префиксу базиса. Решето не заставляют строить список всех простых окна или считать все пустоты: оно также возвращает только максимум и закрытый суффикс.

Для короткого окна вычисление начала прогрессии включает несколько арифметических операций и ветвлений на каждый простой. У кандидатного варианта основная проверка простого p для адреса n — операция `n % p` с ранним выходом. Это объясняет, где реализации расходуют работу; точное процентное разложение разницы времени по этим причинам данным протоколом не измерялось.

## 4. Как сверялось быстродействие

### Одинаковая основная задача

Каждый движок самостоятельно проходит 28 вспышек и получает одинаковую итоговую цепочку с **31 различным окном**. Общий контракт — максимальный простой адрес и точный закрытый суффикс. Наш вариант дополнительно сохраняет конкретные делители составных адресов; от конкурентов выдача этих делителей не требуется.

Готовые ответы не передаются рабочим алгоритмам. Маршрут каждого движка строится из его собственных ответов; совпадение проверяется после остановки таймера.

### Порядок и условия замеров

- Три движка: `candidate_prime`, `segmented`, `mr12_candidates`.
- 12 раундов, по одному запуску каждого движка: всего 36 наблюдений.
- Все шесть порядков трёх движков выполнены дважды.
- Перед каждым наблюдением создаются новый движок и новый базис. Внутри его маршрута состояние сохраняется между вспышками.
- Все наблюдения проходят в одном процессе после общих импортов. Аппаратные кэши и файловый кэш операционной системы принудительно не очищаются.
- Перед стартом выполняется `gc.collect()`, но автоматическая сборка мусора во время расчёта остаётся включённой.
- Замер: `time.perf_counter_ns()`, реальное прошедшее время.
- Процесс закрепляется за одним разрешённым логическим CPU: CPU 8, если доступен, иначе первым разрешённым. Это номер CPU, а не восемь потоков.
- Диагностика рабочих циклов в канонических замерах выключена.

**В таймер входят** создание движка, построение и расширение его базиса, поиск всех окон, общий контроллер, сохранение ответов и формирование результата маршрута. **За таймером находятся** импорты, предварительный сбор мусора, сравнение результатов, запись JSON и удаление объектов после наблюдения.

### Проверка ответов

После каждого замера сравнивается сигнатура: вся цепочка опор, все `B,L,R`, максимумы окон, границы суффиксов, признак нулевого числа пустот и сведения о шагах. Совпали **1116 ответов окон**: 31 окно × 36 наблюдений. Итоговая опора всех маршрутов — **63 286 095 838 211**.

В каноническом сравнении третьим независимым движком выступает MR по первым 12 простым основаниям 2–37, ограниченный диапазоном `n<2^64`. Это точный вариант на заявленном диапазоне, а не вероятностное снижение качества. Основание: [Sorenson–Webster, Strong Pseudoprimes to Twelve Prime Bases](https://arxiv.org/abs/1509.00864).

При отдельном запуске `flash_candidates.py` модуль `candidate_validation.py` импортируется только после завершения рабочего расчёта и остановки его таймера. Он независимо проверяет простоту максимумов, отсутствие простых в суффиксах, равенства `d*m=n`, полноту списка свидетелей и границу заявленного перебора. Диагностический запуск нашего варианта подтвердил 120 факторных свидетельств и 28 сертификатов максимумов. Валидация результата не является заверением каждой внутренней инструкции процессора; общая точность алгоритма следует из полного базиса и доказательства в статье.

## 5. Измеренные результаты

Медиана времени **всего маршрута**, миллисекунды:

| Движок | Исходный опыт | Сохранённый повтор |
|---|---:|---:|
| `candidate_prime` | 263,506 | 294,488 |
| `segmented` | 713,200 | 826,170 |
| `mr12_candidates` | 2,035 | 2,219 |

Для каждого раунда сначала вычисляется отношение времён `segmented / candidate_prime`, затем берётся медиана 12 отношений. Получены **2,788** исходно и **2,760** в повторе. Наш вариант быстрее решета в **11 из 12** исходных и **12 из 12** повторных пар.

Это не отношение двух отдельных медиан. Точный MR12 быстрее нашего варианта во всех исходных и повторных парах; медианы парных отношений `candidate_prime / MR12` равны **144,492** и **143,805**.

Первичные времена каждого запуска находятся в `data/benchmark_original_observations.csv`; повтор — в `data/benchmark_rerun_observations.csv`. Файлы `*_medians.csv` и `*_summary.csv` содержат медианы и парные отношения. JSON сохраняют параметры, окружение, порядок и контроль исходников.

Эти наблюдения не устанавливают быстродействие на полном перечислении простых, на других длинах окон, на рекордном P или в сравнении с оптимизированными реализациями решёт C/C++. Для этих вопросов нужны отдельные измерения с соответствующей задачей.

## 6. Команды запуска

Откройте терминал в корне распакованного пакета. Для численных программ нужна только стандартная библиотека Python 3.10+.

**Проверка сохранённых исходников и исходных данных без новых замеров:**

```bash
python src/reproduce.py
```

**Запуск измеренного кандидатного алгоритма с независимой проверкой результата:**

```bash
python src/candidate_work/flash_candidates.py --mode candidate_prime --flashes 28 --output data/candidate_prime_run.json
```

**Запуск того же контроллера с сегментным решетом:**

```bash
python src/candidate_work/flash_candidates.py --mode segmented --flashes 28 --output data/segmented_run.json
```

Два одиночных запуска удобны для проверки, но не заменяют сбалансированный парный протокол.

**Полный повтор канонического сравнения на Linux или WSL:**

```bash
python src/reproduce.py --benchmark
```

Команда правильно устанавливает рабочий каталог для неизменённого `strong_baseline_probe.py`. Новые данные сохраняются в `benchmark_rerun.json` и соответствующие CSV; исходные `benchmark_original*` сохраняются.

**Счётчики работы отдельно от парных замеров:**

```bash
python src/candidate_work/flash_candidates.py --mode candidate_prime --flashes 28 --profile --output data/candidate_prime_profile_rerun.json
python src/candidate_work/flash_candidates.py --mode segmented --flashes 28 --profile --output data/segmented_profile_rerun.json
```

На Windows можно заменить `python` на `py -3`. Обычные запуски движков работают и без Linux, а неизменённый канонический протокол требует Linux/WSL из-за CPU affinity. При изменении кода старые измерения сохраняют смысл только для прежней версии: проверка снимков специально обнаруживает такую подмену.

Новый сертификат поглощения старых теней у рекордного P описан отдельно в основном README. Он включён в пакет и проверяется через `run_all.py`; его время не смешивается с этим маршрутом поиска простых.
