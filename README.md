# Многомерные пространства, тени и миры вспышек

**Воспроизводимый исследовательский пакет, версия 1.0.0, 10 октября 2026 года. Автор: Вадим.**

## Что доказано аналитически

Доказательства приведены в статье; конечные тесты проверяют их программное воплощение.

1. **Координаты и слои.** Числу соответствует единственный вектор степеней простых. При фиксированной степени `k` последней оси `q` слой `q^k*m <= X` после деления на `q^k` совпадает с миром предыдущих осей при границе `floor(X/q^k)`. Единица включена как нулевой вектор. Для комплексного веса справедливо `(q^k*m)^(-s) = q^(-k*s)*m^(-s)`.
2. **Точность конечного мира.** Для нечётного `B >= 3` определены `S_B = {p*m: p — нечётное простое <= B; m нечётно, 3 <= m <= B}` и `G(B) = min(B^2, 3B+4)`. На нечётных адресах от 3 до `G(B)` множество `S_B` содержит ровно составные числа. `G(B)` — достаточная безопасная граница; её максимальность не заявлена.
3. **Обрезка с сохранением ответа.** При `C' ⊆ C` равенство `C' ∪ U = C ∪ U` выполняется тогда и только тогда, когда `C \ C' ⊆ U`. Удалять можно лишь покрытие, заменяемое оставленными тенями. Одного сохранённого делителя достаточно для удостоверения составности адреса.
4. **Сохранение закрытых адресов.** Найденный делитель остаётся делителем при переходе к новому миру. Доказанную простоту адреса также не нужно вычислять заново. Адреса и сертификаты можно хранить непосредственно.
5. **Остаточный слой тени.** В безопасном окне остаток тени `p` после всех более поздних простых осей состоит в точности из составных чисел, у которых `p` — наибольший простой делитель. Это дизъюнктное объединение исходных слоёв `p^k*m`, где `m` содержит только меньшие нечётные простые либо равно единице; одиночное `p` исключается.
6. **Левый предел полного суффикса осей.** Если в окне есть составные адреса, самое позднее допустимое начало полного суффикса равно `a* = min P⁺(n)` по этим адресам. Произвольный разреженный сертификат не обязан хранить все оси суффикса.
7. **Поглощение блока старых осей без поиска поздних владельцев.** Пусть `D_Y(n)=∏ p^v_p(n)` — полный делитель числа, составленный из всех простых до Y. Если `D_Y(n)<n` во всём безопасном окне, все старые тени `p<=Y` поглощены более поздними. Остаток `n/D_Y(n)>1` имеет простой делитель больше Y; для составного адреса этот делитель является допустимой осью. Полная факторизация числа не требуется.

Координатный мир произведений `H_r(X)` и конечный нечётный мир `S_B` описаны отдельно. Равенство их определений не предполагается. Совпадение занятости после обрезки также не означает сохранения кратностей владельцев или всех комплексных сумм.

## Рябь и глубина сохраняемой истории

Рябь рассматривается как изменение неперекрытого остатка старых теней в текущем окне. Вопрос — насколько далеко влево от опоры нужно сохранять действующие правила покрытия. Оценка полного базиса делителей до квадратного корня на этот вопрос не отвечает.

Пусть `T_p(I)` — след простой оси `p` в окне. После перекрытия всеми более поздними простыми остаётся

$$
\mathcal R_{p,B}(I)=T_p(I)\setminus\bigcup_{p<q\le B}T_q(I)
=\{n\in I:n\text{ составно},\ P^+(n)=p\}.
$$

Здесь `P⁺(n)` — наибольший **простой** делитель. Равенство относится к безопасному окну `I ⊆ [3,G(B)]`. Если у `n=p*m` есть простой делитель `q>p`, то `q` делит `m`, а `n/q < m <= B`: адрес закрывается поздней тенью. Обратное следует из допустимости простых делителей в безопасной области.

Это точная связь с первоначальными «блинами». Каждый адрес остатка единственным образом имеет вид `p^k*m`, где `k>=1`, а `m` состоит из меньших нечётных простых; разрешено `m=1`. Разделение слоя на `p^k` переносит его в предыдущий координатный мир. Ось не добавляет покрытия, если ни один такой остаточный слой не попал в окно. Комплексные веса этих слоёв можно переносить множителем `p^(-k*s)`, однако решение о пустоте должно опираться на точное покрытие.

Для блока всех осей до Y это даёт проверяемое правило через полную малую часть `D_Y(n)`. Например, при Y=5 у числа `195` она равна `3*5=15`; остаток 13 обеспечивает заменяющую позднюю ось. У `625=5^4` малая часть равна самому числу: более поздней оси нет, остаточный слой 5 сохраняется. При рекордном P такую проверку удалось завершить для всех 1500 позиций; результат приведён ниже.

Для непрерывного полного суффикса осей `[a,B]` точная граница:

$$
a_* = \min_{\substack{n\in I\\n\text{ составно}}} P^+(n).
$$

Все составные адреса покрываются суффиксом тогда и только тогда, когда `a <= a*`. Если составных нет, покрывающий суффикс не нужен. Глубина такого суффикса равна `pi(B)-pi(a*-1)`. Можно также оставить только множество различных наибольших простых делителей адресов; оно даёт разреженное покрытие, но не обязательно покрытие с минимальным числом осей.

### Поглощённая тень может вернуться

В мире `B=71` окно равно `[189,217]`. След 5 состоит из адресов `195,205,215`; он полностью покрывается поздними осями:

```text
195 = 13 * 15
205 = 41 * 5
215 = 43 * 5
```

Следующая настоящая вспышка даёт `B=211`. В новом окне `[609,637]` находится `625=5^4`: его единственная простая ось — 5. Это пример перехода от начального мира 71, отдельно от канонической цепочки от 3.

Для оси 1013 построены отдельные точные примеры:

| Опора B | Окно | Единственный адрес тени 1013 | Результат |
|---:|---|---|---|
| 1 013 | [3015,3043] | `3039=3*1013` | Остаток непуст |
| 344 083 | [1032225,1032253] | `1032247=1013*1019` | Непустая тень полностью поглощена осью 1019 |
| 1 710 287 | [5130837,5130865] | `5130845=5*1013^2` | Остаток снова непуст |

Эти специально выбранные простые опоры не заявляются соседними вспышками. Их простота, полный след 1013 и указанные факторизации проверены точно; остальные адреса этими примерами не классифицируются. Протокол: `data/ripple_1013.json`.

На последовательности всех простых опор до 5000 зарегистрировано 107 возвращений осей 5, 7 и 13 после периода ненужности. В 14 выбранных мирах канонической цепочки возвращений этих трёх осей не обнаружено; такая конечная выборка не доказывает постоянного исчезновения. В данных различаются отсутствие точек тени в окне и поглощение её непустого следа.

Поэтому сохраняем адреса и найденные делители, описания слоёв, сертификаты поглощения и область их действия. Период исключается из текущего расчёта после подтверждённого покрытия. Перенос сертификата в новое окно требует доказанного правила или проверки только вновь затронутых слоёв. Эти условия предотвращают потерю старых сведений и повторное восстановление уже сохранённых адресов.

## Точность: наш метод, решёта и Миллер — Рабин

**Завершённая точная версия нашего метода выявляет любое составное число:** у него обязательно есть простой делитель не больше квадратного корня. Текущий кандидатный движок проверяет полный необходимый набор делителей и сохраняет конкретный делитель для каждого исключённого адреса. Сильные псевдопростые исключаются на том же основании.

| Режим | Что означает оставшийся адрес | Гарантия |
|---|---|---|
| Наш полный точный тест | Доказанное простое | Составное не принимается за простое |
| Точное решето с достаточным базисом | Доказанное простое | Та же гарантия точности |
| Наш ограниченный фильтр до заданного предела | `UNKNOWN` | Найденный делитель достоверен; отсутствие малого делителя не доказывает простоту |
| Вероятностный Миллер — Рабин | Вероятно простое | Может пропустить составное на выбранных основаниях |
| MR по первым 12 простым основаниям при `n < 2^64` | Доказанное простое в заявленном диапазоне | Вероятностной ошибки в этом диапазоне нет |

Для фиксированного нечётного составного ошибка вероятностного MR после `k` независимых равномерно случайных оснований не превышает `4^(-k)`. Это вероятность по выбору оснований для фиксированного составного, а не автоматически вероятность составности любого принятого кандидата. Ответ MR «составное» достоверен. Основание для этих утверждений: [Handbook of Applied Cryptography, §4.2.3](https://cacr.uwaterloo.ca/hac/about/chap4.pdf).

В частности, `2047 = 23*89` проходит один сильный раунд по основанию 2, но закрывается нашим точным тестом делителем 23. Это пример ограничения одного основания. Он не опровергает точность MR64. Достаточность первых 12 простых оснований в нашем диапазоне следует из [Sorenson–Webster, Strong Pseudoprimes to Twelve Prime Bases](https://arxiv.org/abs/1509.00864). Код явно отклоняет выход за `2^64`.

## Как получен `3P-82`

Исходное число: `P = 2^136279841 - 1`, известное простое Мерсенна ([GIMPS](https://www.mersenne.org/primes/?press=M136279841)). Для него `R = 3P+4`.

Адреса окна записываются как `N_j = R-2j`, начиная с `j=0`. Проверяются только нечётные позиции. Все первые 43 позиции `j=0..42` получили точные делители; последний из них, `3P-80`, делится на 11. Следующий адрес:

```text
j = 43
N_43 = 3P + 4 - 2*43
     = 3P + 4 - 86
     = 3P - 82
     = 3*2^136279841 - 85
```

Это **44-я рассматриваемая нечётная позиция**, после 43 исключённых. Смещение 82 получилось из 86−4. Для проверки делимости используются точные остатки `pow(2, E, p)`; огромный P целиком не создаётся.

Всего проверены 1500 позиций и 78 497 нечётных простых до миллиона. Для 1381 адреса найден делитель; 119 адресов остаются `UNKNOWN`. В частности, для `3P-82` делитель в этом диапазоне не найден. **Это не доказанное новое простое и не утверждение о ближайшем простом после P.** Подтверждён закрытый участок справа и выделен следующий кандидат для дальнейшей проверки.

Точные делители, параметры, исходники и повтор находятся в `data/record_original.json`, `data/record_rerun.json`. Видео `figures/shadows_and_flash.mp4` показывает постепенное закрытие первых 44 позиций. Незаполненные клетки в видео обозначают неизвестный статус.

## Сертификат ряби при рекордном P

**Для всего окна `N_j=3*2^136279841+1-2j`, `j=0..1499`, доказано поглощение всех простых осей до миллиона более поздними осями.** В частности, остатки осей 5, 7, 13 и 1013 пусты. Полный ряд простых до P и полные факторизации этих огромных адресов не строились.

Вычисление использует полную малую часть:

$$
D_Y(N_j)=\prod_{p\le Y}p^{v_p(N_j)},\qquad Y=10^6.
$$

Сначала для каждого нечётного простого p вычисляется `pow(2,E,p)`. Попавшие в окно позиции находятся одной прогрессией по j. Степени `p²,p³,...` проверяются только у непустых следов. Подъём продолжается до первого ненулевого остатка; тем самым определяются **полные** степени, без произвольного обрыва. Программа сохраняет точные свидетельства делимости на `p^v` и неделимости на `p^(v+1)`, таблицу малых разложений и отдельную проверку произведений.

| Показатель сертификата | Значение |
|---|---:|
| Адресов окна | 1500 |
| Нечётных простых до Y | 78 497 |
| Простых с непустым следом | 1 161 |
| Наибольшая степень малого простого | 6 |
| Максимальный размер полной малой части D_Y | **80 бит** |
| Адресов с D_Y>1 | 1381 |
| Адресов с D_Y=1 | 119 |

Все адреса превосходят `2^136279841`, а все малые части имеют не более 80 бит. Поэтому `D_Y(N_j)<N_j` доказывается точной оценкой длины, без создания самого P. У каждого уже составного адреса есть допустимый простой делитель больше миллиона. Этого достаточно для доказательства поглощения; конкретное имя большого делителя не вычислялось.

Контрольные значения:

```text
D_Y(N_0)  = 1018492194103 = 53*439*1039*42131
D_Y(N_13) = 139291
D_Y(N_17) = 1152208172826291812625387  (максимум, 80 бит)
D_Y(N_25) = 483167
D_Y(N_43) = 1
```

Это также даёт границы начала полного суффикса простых осей для **всего окна из 1500 адресов**:

$$
10^6<a_*\le\frac{3P-30}{1152208172826291812625387}
<2{,}603697\cdot10^{-24}P.
$$

Для верхней границы используется `N_17=3P-30`. Оно больше квадрата своего полного малого делителя D; поэтому любой его простой делитель не превосходит `N_17/D`. Данные отдельно удостоверяют это неравенство малыми целыми числами. Границы точны, но промежуток всё ещё огромен: это пока не практическая оценка полного оставшегося ряда. Его длина также не является необходимым размером разреженного мира уточняющих правил.

**Что сертификат меняет:** отдельные периоды старых осей до миллиона больше не нужны для представления остаточных слоёв этого окна, если сохраняется доказанное правило поглощения. Уже найденные адреса, малые делители и сертификаты составности остаются полезными сохранёнными ответами.

**Что остаётся открытым:** для 119 адресов с `D_Y=1` простота не установлена. Большой простой делитель может оказаться самим адресом, если он прост. Поэтому сертификат не превращает `3P-82` в доказанную пустоту и не предъявляет поздних владельцев для неизвестных составных. Нужна дальнейшая работа по оставшимся слоям и точным сертификатам кандидатов.

Код: `src/ripple_smooth_certificate.py`. Полные проверяемые данные: `data/ripple_smooth_certificate.json`, `data/ripple_smooth_certificate.csv`. Этот расчёт является дополнительным сертификатом покрытия; его служебное время не подставляется в таблицу сравнения поисковых движков.

Снимок сделан 10.10.2026 в 18:35:47 UTC, то есть 21:35:47 по Москве. Источник — `data/resources.json`; программу измерения можно запустить самостоятельно.

Не следует принимать память или полное оборудование физического хоста за ресурсы этой вычислительной среды. Отсутствие видимых устройств GPU характеризует доступ контейнера.

Двоичная запись самого P занимает **17 034 981 байт ≈ 16,25 МиБ** без накладных расходов представления. Для реализованной проверки полным перебором барьер находится в количестве возможных делителей. При `R=3P+4`:

```text
log10(sqrt(R)) ≈ 20 512 160,2112
pi(sqrt(R))   ≈ 3,44344 × 10^(20 512 152)
```

Количество простых оценено асимптотикой `pi(x) ~ x/ln(x)`. Даже условный полный проход при **10^12 проверок/с**, с нулевой ценой построения, хранения и получения базиса, дал бы около **1,09116 × 10^(20 512 133) лет**. Это оптимистическая модель текущего исчерпывающего прохода, не замер, не строгая нижняя оценка и не предел для всех способов доказать простоту. **Она не вычисляет глубину ряби и не является оценкой необходимого объёма мира сохраняемых правил.** Если у кандидата найдётся доступный малый делитель, он исключается намного раньше.

Следовательно, увеличение количества ядер или памяти само по себе не делает текущую полную проверку рекордного кандидата практической. Локальная обрезка полезна и воспроизведена; достаточного нового сертификата для `3P-82` пока нет. Ресурсное ограничение объясняет незавершённость проверки, но не является аргументом в пользу простоты кандидата.

## Что не подтвердилось или ещё не получено

- Универсальное правило, которое по мерности или комплексной картине сразу выдаёт следующее простое без достаточной проверки, в этой версии не получено.
- Постоянное исчезновение прежней оси после её поглощения в одном окне не следует из локального сертификата; переход 71→211 показывает возвращение оси 5 в настоящем новом окне.
- Нулевая комплексная сумма не заменяет точный сертификат отсутствия адресов.
- Превосходство над решётами в целом не установлено; сравнение с нашим Python-решетом имеет ограниченную область применения.
- Превосходство текущего точного кандидатного движка над MR64 в данном опыте опровергается измерениями: MR64 быстрее во всех 12 исходных и 12 повторных раундах.
- Простота `3P-82`, новая доказанная пустота за выбранным P и практически выполнимое построение полного точного мира этого масштаба не получены.

## Быстрое воспроизведение

Распакуйте пакет и откройте терминал в его корне. Для арифметических программ достаточно **Python 3.10+**; замеры поставлены на Python 3.12.14. Базовые проверки работают на Windows, Linux и macOS.

```bash
python src/run_all.py
```

Команда проверяет неизменность измеренных исходников и исторических CSV, воспроизводит символический опыт, сверяет конечные миры, запускает независимый учебный self-check, пилот ряби, примеры оси 1013, сертификат поглощения при рекордном P и сохраняет новый снимок ресурсов. Отчёт: `data/package_verification.json`. Исходные измерения не перезаписываются; повторные результаты получают суффикс `_rerun`.

В Windows можно использовать `py -3` вместо `python`. **Точный канонический протокол сравнения требует Linux или WSL**, потому что сохранённый исходник использует CPU affinity:

```bash
python src/reproduce.py --benchmark
```

Для отдельного простого примера:

```bash
python src/flash_worlds_demo.py flashes --count 15
python src/flash_worlds_demo.py record-probe --limit 1000000 --width 1500
python src/flash_worlds_demo.py self-check
python src/flash_worlds_demo.py benchmark --count 20 --rounds 6
```

Последняя команда сравнивает учебные движки; её времена не являются каноническими данными статьи. Код точного ядра в учебном примере остаётся целочисленным, с прямым хранением адресов и факторных свидетельств.

### Рисунки, видео и статья

```bash
python -m pip install -r requirements-figures.txt
python src/make_figures.py --video
python src/make_ripple_figure.py
python src/build_paper.py
```

Для видео установите **FFmpeg с libx264** и добавьте его в PATH. Для PDF установите **XeLaTeX** (TeX Live либо MiKTeX), пакеты `fontspec`, `polyglossia`, `amsmath`, `amssymb`, `booktabs`, `tabularx`, `graphicx`, `xcolor`, `fancyhdr`, `ragged2e`, `caption`, `float`, `hyperref` и шрифты **DejaVu**. ```bash
python src/run_all.py --benchmark --media --paper

Точные результаты арифметики должны совпасть. Времена, снимок доступных ресурсов и побайтовый результат PDF/MP4 могут различаться из-за оборудования, планировщика и версий средств сборки. Исторические JSON содержат снимки использованных исходников; подмена их учебным файлом обнаруживается проверкой.

`SHA256SUMS` фиксирует состояние архива при выпуске. Повторный запуск закономерно меняет файлы `_rerun`, служебные отчёты и пересобранные медиа; контрольные суммы исходной поставки проверяют до таких изменений. Протокол запуска после распаковки включён в `data/release_validation.json`.
