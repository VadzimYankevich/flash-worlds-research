# Формальная проверка конечного нечётного мира

Этот каталог содержит локально проверяемую формализацию на Lean 4. Она относится
только к конечному миру покрытия на нечётной оси; это не формализация гипотезы
Римана и не заявление о её доказательстве.

## Что именно доказывается

Для нечётной границы B >= 3 определяются:

- S_B как конечное множество произведений p * m, где p — нечётная
  простая ось, 3 <= p <= B, а m — нечётный множитель, 3 <= m <= B;
- сертифицированная граница G(B) = min(B^2, 3B + 4);
- безопасное окно нечётных адресов 3 <= n <= G(B).

Главные проверяемые утверждения:

1. В безопасном окне адрес занят тогда и только тогда, когда он составной.
2. При переходе B <= B' заполнение старого безопасного окна не меняется.
3. Вычислимое конечное множество дыр совпадает с вычислимым конечным множеством
   простых в том же окне, поэтому их мощности равны.

Покрытие задаётся произведениями осей и множителей, а не определением через
простоту или составность. Равенство с составными и простыми доказывается после
этого отдельно.

## Границы результата

Ось 2 намеренно не входит в модель. Условия «B нечётно», «B >= 3» и
«n нечётно» входят в формулировки теорем. Утверждение о наследовании относится
к уже сертифицированному старому окну, а не к новому участку оси. В формальной
теореме для следующей границы достаточно B <= B': это корректное усиление
исходной формулировки, где последующая граница мира также нечётна. Здесь нет
оценки отклонения распределения простых, комплексного анализа или утверждения
о RH.

## Воспроизведение

Нужны Lean v4.35.0 и Lake. После получения зависимостей Lake:

    lake update
    lake build
    lake build PrimeWorldsFormal.AxiomAudit
    lake env lean PrimeWorldsFormal/AxiomAudit.lean
    lake env leanchecker --fresh PrimeWorldsFormal.AxiomAudit

\`AxiomAudit.lean\` содержит строгие \`#guard_msgs\`: для логических и вычислимых
форм трёх результатов допускаются ровно стандартные основания ядра Lean
\`propext\`, \`Classical.choice\` и \`Quot.sound\`. Добавление пользовательского
допущения или незавершённого доказательства меняет вывод и ломает аудит.

Подробности фактического локального прогона приведены в
[VERIFICATION.md](VERIFICATION.md). В этот каталог намеренно не добавляются
GitHub Actions или иной CI: проверки выполняются локально по командам выше.
